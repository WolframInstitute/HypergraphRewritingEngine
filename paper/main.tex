\begin{abstract}
The Wolfram Physics Project models fundamental physics through hypergraph rewriting systems, where the evolution of simple rules generates complex causal and branchial structures. However, exhaustive multiway evolution is computationally intensive, with naive implementations exhibiting exponential time complexity in the number of evolution steps. We present a high-performance implementation built around three components: (1) exact graph canonicalization by McKay-style individualization--refinement (IR), which under the exact mode runs on every state and whose hash serves directly as the deduplication key. We show that interposing a cheaper Weisfeiler--Leman filter cannot reduce the number of IR invocations by more than the ratio of canonical classes to raw states, a ratio that decreases with evolution depth; (2) lock-free concurrent data structures enabling parallel evolution across many CPU cores; and (3) a GPU evolution backend. Canonicalization is validated for exactness against a brute-force isomorphism oracle and cross-checked against the Wolfram \texttt{MultiwaySystem} paclet, so state and event deduplication are exact rather than heuristic. The system is available as both a standalone C++/CUDA library and a Wolfram Language paclet.

\vspace{0.5em}
\noindent Every quantitative table in Section~\ref{sec:benchmarks} is generated from the tools that produce it, and each carries the commit, the machine and the tool in its own provenance line. The machine is a desktop under WSL2 shared with other work, whose wall-clock measurements vary by more than ten percent between runs; the tables report medians, and state explicitly where a measured difference is smaller than that variation.

\vspace{1em}
\noindent\textbf{Keywords:} hypergraph rewriting, graph canonicalization, multiway systems, GPU computing, Wolfram Physics Project
\end{abstract}

\section{Introduction}
\label{sec:introduction}

The Wolfram Physics Project~\cite{wolfram2020project} proposes that the fundamental structure of the universe emerges from the repeated application of simple rewriting rules to hypergraphs. This approach generates three derived structures: causal graphs, recording dependencies between rewriting events; branchial graphs, connecting states reachable at the same evolution step; and multiway evolution graphs, representing the set of all reachable histories.

Exhaustive multiway evolution is computationally demanding. The number of reachable states grows exponentially with the number of evolution steps, and each step requires pattern matching against the current hypergraphs, canonicalization to identify isomorphic duplicates, and event recording to construct the causal and branchial structures. The reference implementation in Wolfram Language is mathematically complete but, as Section~\ref{sec:benchmarks} quantifies, its running time makes evolutions beyond a few hundred states impractical.

This paper presents a high-performance implementation addressing these challenges through:

\begin{enumerate}
    \item \textbf{Exact canonicalization:} We use McKay-style individualization--refinement (IR)~\cite{mckay2014practical} as the canonicalizer, and under the exact mode it runs on every state: its hash is the deduplication key, so two states are identified if and only if they are isomorphic. A Weisfeiler--Leman signature~\cite{weisfeiler1968reduction} serves the approximate modes, which exist for callers that ask for a coarser identity. Proposition~\ref{prop:wlceiling} shows why it is not placed in front of IR: the saving available to such a filter is bounded above by the ratio of canonical classes to raw states, which falls toward zero as an evolution deepens.

    \item \textbf{Lock-free concurrency:} Our data structures---concurrent hash maps, segmented arrays, lock-free lists---enable parallel evolution without contention bottlenecks.

    \item \textbf{GPU acceleration:} A GPU evolution backend offloads pattern matching and canonicalization for suitable workloads.

    \item \textbf{Configurable equivalencing:} State and event equivalencing are independent axes. State canonicalization is selected as \textsc{None}, \textsc{Automatic} (fast content hash), or \textsc{Full} (exact IR); event canonicalization is composed from a small set of signature keys. There is no user-facing choice between competing canonicalization algorithms---the exact path is always IR, computed on every state.

    \item \textbf{Exploration strategies:} Quotient exploration (Section~\ref{sec:quotient}) expands one representative per isomorphism class while retaining the full event set; transition-level sampling with per-rule weights (Section~\ref{sec:sampling}) admits runs at depths where exhaustive expansion is not available; and the causal graph's transitive reduction (Section~\ref{sec:tr}) is maintained online rather than as a pass over the finished graph.

    \item \textbf{A determinism contract:} The state set, event set and causal and branchial relations are a function of the inputs alone, independent of thread count and scheduling order (Section~\ref{sec:determinism}).
\end{enumerate}

The remainder of this paper is organized as follows. Section~\ref{sec:background} reviews hypergraph rewriting and the Wolfram Physics framework. Section~\ref{sec:canonicalization} presents our canonicalization algorithms. Section~\ref{sec:pattern-matching} describes the pattern matching system. Section~\ref{sec:architecture} details the system architecture. Section~\ref{sec:gpu} covers GPU acceleration. Section~\ref{sec:benchmarks} presents experimental results. Section~\ref{sec:conclusion} concludes with future directions.

\section{Background and Related Work}
\label{sec:background}

\subsection{Hypergraph Rewriting Systems}

A \emph{hypergraph} $\hypergraph = (V, E)$ consists of a vertex set $V$ and a set of hyperedges $E$, where each hyperedge $e \in E$ is an ordered tuple of vertices $(v_1, v_2, \ldots, v_k)$ with $v_i \in V$. Unlike standard graphs where edges connect exactly two vertices, hyperedges may connect any number of vertices with arbitrary arity.

\begin{definition}[Rewriting Rule]
A rewriting rule $\rewriterule = (L, R)$ consists of a left-hand side pattern $L$ and right-hand side replacement $R$, both hypergraphs. A \emph{match} of $L$ in $\hypergraph$ is an injective mapping $\phi: V_L \to V_\hypergraph$ such that the image of each hyperedge in $L$ appears in $\hypergraph$.
\end{definition}

Applying rule $\rewriterule$ at match $\phi$ produces a new hypergraph $\hypergraph'$ by:
\begin{enumerate}
    \item Removing all hyperedges in $\phi(L)$ from $\hypergraph$
    \item Adding hyperedges from $R$, extending $\phi$ to map new vertices in $R$ to fresh vertices
\end{enumerate}

\subsection{Multiway Evolution}

\emph{Multiway evolution} explores all possible rule applications simultaneously, generating a directed acyclic graph of states connected by events.

\begin{definition}[Evolution Graph]
Given initial state $\state_0$ and rule set $\{\rewriterule_i\}$, the evolution graph $G = (\state, \event)$ contains:
\begin{itemize}
    \item States $\state$: all hypergraphs reachable from $\state_0$
    \item Events $\event$: transitions $(s, s', r, \phi)$ where state $s$ rewrites to $s'$ via rule $r$ at match $\phi$
\end{itemize}
\end{definition}

The \emph{causal graph} captures dependencies between events based on shared hyperedges. The \emph{branchial graph} connects states reachable at the same evolution step, encoding branching structure analogous to quantum superposition~\cite{wolfram2020project}.

\subsection{The Graph Isomorphism Problem}

State deduplication requires detecting when two hypergraphs are isomorphic---structurally identical up to vertex relabeling. Graph isomorphism is known to be in NP but not known to be NP-complete or in P, occupying a unique complexity-theoretic position~\cite{babai2016quasipolynomial}.

For practical systems, we employ \emph{graph hashing}: computing a canonical signature $h(\hypergraph)$ such that isomorphic graphs have identical hashes. While perfect hashing (injective for non-isomorphic graphs) requires solving isomorphism exactly, approximate hashes suffice when combined with explicit isomorphism testing for collisions.

\subsection{Related Work}

\textbf{Graph canonicalization:} The nauty/Traces line of work~\cite{mckay2014practical} establishes individualization--refinement (IR) as the practical standard for exact graph canonicalization; it is exponential in the worst case but fast on typical instances, and it is the exact canonicalizer we adopt as our reference. Weisfeiler--Leman color refinement~\cite{weisfeiler1968reduction,shervashidze2011weisfeiler} runs in polynomial time but provably fails to distinguish certain non-isomorphic graphs, so it cannot serve as an identity where exactness is required; we use it only for the modes that ask for a deliberately coarser identity, never in front of IR. Uniqueness trees~\cite{gorard2016uniqueness} were proposed as a polynomial approach to graph isomorphism; we do not use them---the approach does not give a sound canonical form for our workloads, and IR provides the exactness guarantee we require.

\textbf{Subgraph matching on hypergraphs:} HGMatch~\cite{yang2023hgmatch} matches by hyperedge rather than vertex by vertex, seeding a join from one pattern hyperedge and extending it one hyperedge at a time, and partitions candidate hyperedges by a label-derived signature to restrict enumeration. Our matcher adopts both. The join is organised as a seeding scan followed by expansions that each bind one further pattern edge (Section~\ref{sec:matching-algorithm}), and because hyperedges here carry no labels, the signature that partitions candidates is instead the vertex-repetition pattern of an edge (Definition~\ref{def:signature}), which plays the same filtering role for unlabelled data. Where an expansion has a variable already bound, candidates come from the vertex index rather than the signature bucket; on the device this replaced a global signature walk and reduced match-kernel time on one workload from 944\,ms to 4\,ms.

\textbf{GPU graph algorithms:} Recent work has explored GPU acceleration for subgraph matching~\cite{tran2015fast}, graph mining~\cite{chen2021pangolin}, and general graph algorithms~\cite{wang2016gunrock}. The warp-centric organisation of our match kernel---one block per (state, rule) pair, threads striding over seed candidates and each running its own depth-first subtree---follows G2Miner~\cite{chen2022g2miner}. Our kernel differs from these systems in remaining resident across evolution steps rather than being relaunched per step, because the workload is iterative: each step's states are the next step's inputs.

\textbf{Term rewriting:} High-performance term rewriting systems~\cite{van2019fastest} optimize similar pattern matching operations but typically assume tree-structured terms rather than graph-structured hypergraphs.

\section{Graph Canonicalization}
\label{sec:canonicalization}

Efficient state deduplication is critical for multiway evolution, as the state space grows exponentially without isomorphism detection. Deduplication must be \emph{exact}: two states are the same node if and only if their hypergraphs are isomorphic (vertex relabeling, within-edge order and multiplicity preserved). The exact mode satisfies this requirement using individualization--refinement (IR) alone: it is computed for every state, and its hash serves directly as the deduplication key. Weisfeiler--Leman (WL) is a separate, coarser signature, used by the modes that request a coarser notion of state identity.

\subsection{Individualization--Refinement (Exact Reference)}
\label{sec:ir}

The exact canonical form is computed by McKay-style individualization--refinement~\cite{mckay2014practical}, the same family of algorithms underlying nauty and Traces. IR produces a canonical labeling---and, as a byproduct, a set of automorphism generators and vertex/edge orbits---such that two hypergraphs receive identical canonical forms if and only if they are isomorphic.

\begin{definition}[Canonical Form]
A canonicalization $\canon$ maps each hypergraph to a labeled representative such that $\canon(\hypergraph_1) = \canon(\hypergraph_2)$ iff $\hypergraph_1 \cong \hypergraph_2$.
\end{definition}

IR proceeds by iterated color refinement to a stable coloring; when refinement leaves a non-singleton cell, it \emph{individualizes} one vertex (assigns it a distinguishing color) and recurses, exploring a search tree of refinements. Automorphisms discovered along the way prune the tree so that symmetric branches are not re-explored, and the lexicographically extremal leaf defines the canonical labeling.

\begin{remark}[Complexity]
Like nauty, IR is exponential in the worst case but fast on typical instances. It gives no polynomial-time guarantee, and we claim none. IR is expensive precisely on highly symmetric (high-automorphism) states, which bounds the exact mode's cost on such inputs; it is nonetheless what the exact mode runs, on every state, for the reason measured in Section~\ref{sec:wl}.
\end{remark}

The automorphism generators and edge orbits produced by IR are reused elsewhere in the engine: they define the canonical edge-orbit equivalence used for principled event canonicalization and for exact offline reconstruction of causal and branchial multiplicities.

\subsection{The Weisfeiler--Leman Signature}
\label{sec:wl}

The engine also computes a 1-dimensional Weisfeiler--Leman (1-WL) color-refinement hash~\cite{weisfeiler1968reduction,shervashidze2011weisfeiler}. WL is a sound but incomplete invariant: isomorphic states always receive the same WL hash, while certain non-isomorphic states --- regular graphs with identical local structure, for instance --- collide. It is the identity used by the modes that request a coarser notion of state equality. It is not used by the exact mode, for the reason established in Proposition~\ref{prop:wlceiling}.

\begin{proposition}[Ceiling on a WL pre-filter]
\label{prop:wlceiling}
Let a run produce $R$ raw states falling into $C$ isomorphism classes. Consider deduplication that computes the WL hash of each raw state, and invokes IR only when that hash has been seen before. Then the number of IR invocations is at least $R - C$, so the fraction of IR calls avoided is at most $C/R$, and one WL pass is paid on all $R$ states.
\end{proposition}

\begin{proof}
WL is isomorphism-invariant, so states in the same class share a WL hash and the number of distinct WL hashes is at most $C$. A state whose WL hash is already present cannot be resolved by WL: equal hashes are consistent both with isomorphism and with a WL collision, so IR is invoked. At most one state per distinct WL hash finds its hash absent, hence at most $C$ states skip IR and at least $R - C$ invoke it.
\end{proof}

The bound is only useful with $C/R$ in hand, and that ratio is a property of the rule and the depth. Measured across the rule-type corpus, reported per case beside the event count, since the two must be read together:

\begin{center}
\begin{tabular}{llrrr}
\toprule
Case & Rule type & Events & $C/R$ & $C/R$ at lower depth \\
\midrule
\texttt{cycle4-automorphic}  & automorphism      & 68{,}184 & 0.0\%  & 0.5\%  \\
\texttt{star4-automorphic}   & automorphism      & 68{,}184 & 0.3\%  & 3.1\%  \\
\texttt{disconnected-lhs}    & disconnected      & 126      & 0.8\%  & 3.2\%  \\
\texttt{binary-growth}       & productive/arity2 & 873      & 4.1\%  & 29.4\% \\
\texttt{multi-rule}          & multi-rule        & 237      & 15.1\% & 15.1\% \\
\texttt{triangle}            & mixed-connected   & 124      & 28.8\% & 28.8\% \\

\bottomrule
\end{tabular}
\end{center}

\noindent For every rule that continues to rewrite, $C/R$ decreases with depth. Reaching the same state along several distinct histories is characteristic of multiway evolution, and each such arrival produces a repeated WL hash that IR must resolve. The cases that retain a high ratio are those reaching a fixed point after one or two steps: \texttt{self-loop} has $C/R = 100\%$ over two raw states and one event. The fraction a filter could elide is therefore largest on the workloads with the least work to elide.

Two options require automorphism data: quotient exploration, and the event canonicalization conventions of Section~\ref{sec:event-canon}. Both obtain the edge orbits from the same IR pass, so no second canonicalization is performed.

\begin{algorithm}
\caption{Weisfeiler-Lehman Hash}
\label{alg:wl}
\begin{algorithmic}[1]
\Procedure{WLHash}{$\hypergraph$}
    \State Initialize $c_v^{(0)} \gets \deg(v)$ for all $v$
    \State $i \gets 0$
    \Repeat
        \State $i \gets i + 1$
        \State \textbf{for} each $v \in V$ \textbf{do}
        \State \quad $c_v^{(i)} \gets \hash(c_v^{(i-1)}, \text{multiset}\{c_u^{(i-1)} : u \in N(v)\})$
    \Until{$\{c_v^{(i)}\} = \{c_v^{(i-1)}\}$} \Comment{partition stable}
    \State \Return $\hash(\text{sorted}(\{c_v^{(i)} : v \in V\}))$
\EndProcedure
\end{algorithmic}
\end{algorithm}

\begin{proposition}[WL Complexity]
1-WL requires $\BigO(|V|^2 \cdot |E|)$ time per iteration, with at most $|V|$ iterations.
\end{proposition}

This polynomial bound is why WL remains available for the coarser modes. It is not an alternative canonicalizer: where exactness is required, IR (Section~\ref{sec:ir}) is the only identity used.

\subsection{State Canonicalization Modes}

Rather than exposing a choice between competing hashing algorithms, the engine exposes a single \emph{state canonicalization mode} that controls how aggressively isomorphic states are merged:

\begin{lstlisting}[language=C++,caption=State canonicalization mode]
enum class StateCanonicalizationMode {
    None,       // keep all states distinct; no dedup
    Automatic,  // content-ordered hash; identifies literal edge content
    Full        // exact: the IR canonical hash, on every state
};
\end{lstlisting}

\textsc{None} performs no deduplication and keeps every raw state distinct. \textsc{Automatic} deduplicates by a content-ordered hash of the edge tuples as given. This hash is not an isomorphism invariant: it identifies states with identical edge content, which is the convention used by the reference implementation. \textsc{Full} is the exact mode used for all correctness-critical results: the IR canonical hash is computed for every state and is itself the deduplication key, so two states are identified if and only if they are isomorphic.

\begin{remark}[Incremental hashing]
Child states differ from their parents by only the consumed and produced edges, so an incremental hash keyed on that delta is attractive. The engine already threads the per-event edge delta to the canonicalizer, but incremental WL hashing is not yet wired into the default path; it is ongoing work rather than a shipped optimization, and no incremental-hashing speedup is claimed here.
\end{remark}

\section{Pattern Matching}
\label{sec:pattern-matching}

Pattern matching---finding all instances of a rule's left-hand side in a hypergraph---accounts for a large fraction of evolution time; the instruction profile in Section~\ref{sec:benchmarks} attributes $23\%$ of executed instructions to the join's expansion step alone. We use multi-level indexing to restrict candidate enumeration.

\subsection{Edge Signature Indexing}

\begin{definition}[Edge Signature]
\label{def:signature}
The \emph{signature} of hyperedge $e = (v_1, \ldots, v_k)$ is the pattern $\sigma(e) = (s_1, \ldots, s_k)$ where $s_i = s_j$ iff $v_i = v_j$.
\end{definition}

For example, edge $(3, 3, 7)$ has signature $(0, 0, 1)$, capturing the repetition pattern without specific vertex labels. Our signature index maps signatures to edge lists:

\begin{equation}
    \text{SigIndex}: \sigma \mapsto \{e \in E : \sigma(e) = \sigma\}
\end{equation}

Pattern edges can match data edges only with compatible signatures. For pattern signature $\sigma_p$ with $d$ distinct variables, the number of compatible data signatures is the Bell number $B_d$~\cite{rota1964number}.

\subsection{Vertex Index}

For bound pattern variables, we maintain an inverted index:
\begin{equation}
    \text{VertexIndex}: v \mapsto \{(e, i) : e_i = v\}
\end{equation}

This enables efficient candidate generation when pattern variables are already assigned from prior edge matches.

\subsection{Matching Algorithm}
\label{sec:matching-algorithm}

Pattern matching proceeds through a task-based system:

\begin{algorithm}
\caption{Task-Based Pattern Matching}
\label{alg:matching}
\begin{algorithmic}[1]
\Procedure{FindMatches}{$L$, $\hypergraph$}
    \State Order pattern edges $e_1, \ldots, e_k$ by selectivity
    \State Enqueue $\textsc{ScanTask}(e_1, \emptyset)$
    \While{task queue non-empty}
        \State $\tau \gets \textsc{Dequeue}()$
        \If{$\tau$ is $\textsc{ScanTask}(e_i, \phi)$}
            \State \textbf{for} each $e \in \text{SigIndex}[\sigma(e_i)]$ \textbf{do}
            \State \quad \textbf{if} $\textsc{Compatible}(e, e_i, \phi)$ \textbf{then}
            \State \quad\quad Enqueue $\textsc{ExpandTask}(e_{i+1}, \phi')$
        \ElsIf{$\tau$ is $\textsc{ExpandTask}(e_i, \phi)$ with $i > k$}
            \State \textbf{yield} complete match $\phi$
        \EndIf
    \EndWhile
\EndProcedure
\end{algorithmic}
\end{algorithm}

\subsection{Match Forwarding}

When state $s'$ is derived from $s$, a match valid in $s$ remains valid in $s'$ unless it used an edge the rewrite removed. The engine forwards such matches from parent to child rather than rediscovering them:

\begin{proposition}[Match Forwarding]
Let $\match$ be a match in state $s$, and let $s'$ be derived from $s$ by applying rule $r$ at match $\match'$. Then $\match$ remains valid in $s'$ iff $\text{edges}(\match) \cap \text{edges}(\match') = \emptyset$.
\end{proposition}

Forwarding therefore avoids re-running the join for every match a child inherits unchanged from its parent. The engine forwards in batches, accumulating a parent's completed matches and delivering them to the child together; Section~\ref{sec:benchmarks} reports the ablation.

\subsection{Lock-Free Data Structures}

Concurrent evolution requires thread-safe data structures without lock contention:

\begin{description}
\item[ConcurrentMap$\langle$K, V$\rangle$:] Hash table using atomic compare-and-swap for insertion. Wait-free lookup with lock-free insertion.

\item[SegmentedArray$\langle$T$\rangle$:] Dynamically growing array stored in fixed-size segments. Append-only with atomic size tracking.

\item[LockFreeList$\langle$T$\rangle$:] Append-only linked list for index entries. Supports concurrent iteration via snapshot semantics.
\end{description}

\subsection{Allocation}
\label{sec:allocation}

Evolution allocates from per-worker arenas rather than from the global allocator. Each worker
holds a bump cursor into blocks it owns, so allocation on the matching and rewriting paths is a
pointer increment with no synchronisation, and memory is reclaimed in bulk by resetting the arena
rather than by freeing individual objects. Calls to the global allocator are consequently confined
to acquiring those blocks: Table~\ref{tab:t3-deheap} reports $58$ to $227$ such calls for an
entire run, which on the largest workload measured is $0.0033$ calls per event.

\subsection{Memory Model}

We employ careful memory ordering to ensure correctness:

\begin{lstlisting}[language=C++,caption=Memory synchronization example]
// Producer: creating new state
edges_.append(new_edge);          // seq_cst store
state.edge_set.insert(edge_id);
std::atomic_thread_fence(std::memory_order_release);
states_.append(state);            // release store

// Consumer: accessing state
StateId id = canonical_map_.lookup(hash);  // acquire load
std::atomic_thread_fence(std::memory_order_acquire);
State& s = states_[id];           // safe to read edge set
\end{lstlisting}

\subsection{Determinism Contract}
\label{sec:determinism}

The engine's observable output---the state set, the event set, and the causal and branchial
relations---is a deterministic function of the rules, the initial state, the step count and the
options. It does not depend on the number of worker threads, on the order in which the scheduler
happens to execute tasks, or on whether quotient exploration is enabled. Identifiers assigned to
states and events are allocated in arrival order and therefore do vary between runs; every
observable defined above is stated over canonical identities and is invariant. This property is
checked by a determinism gate that compares the expanded state set and the (input, output, rule)
transition multiset across thread counts and seeds.

\subsection{Quotient Exploration}
\label{sec:quotient}

Under full expansion, every raw state that is produced is itself expanded, so a state reachable
along $k$ distinct histories is matched against $k$ times. Because the canonical hash already
identifies these as one state, that work is redundant for the purpose of discovering new states.

Quotient exploration retains the events but not the repeated expansion: a state found equivalent
to one already seen is still created, and its incoming event is still recorded, so the event set
and the causal and branchial relations are unchanged; what is suppressed is the spawning of match
tasks from that state. Exploration therefore proceeds from one representative of each isomorphism
class, at the shallowest depth at which the class was reached. Table~\ref{tab:t6-quotient} reports
raw states expanded and wall time for the two modes at increasing depth.

The two modes agree on the canonical state set by construction. They also agree on the causal and
branchial relations, which is less immediate: the relations are defined over raw events, and
quotient exploration produces the same events while expanding fewer states. Reconstructing the
per-instance relations from the quotient run requires the edge orbits, which are obtained from the
IR pass that computed the canonical hash (Section~\ref{sec:ir}), so no additional canonicalization
is performed.

\subsection{Transitive Reduction of the Causal Graph}
\label{sec:tr}

The causal graph accumulates an edge for each dependency between events, including those implied
by longer paths. The transitive reduction removes an edge $p \to c$ whenever a directed path
$p \rightsquigarrow c$ of length greater than one already exists; on an acyclic graph this
reduction is unique.

It is computed online rather than as a pass over the completed graph: each new causal edge is
reduced against the edges already retained. A consumer's incoming edges are processed in
descending producer-event order, so that the reachability closure from nearer producers is
established before farther producers are tested against it. The reduced graph is required to be a
function of the causal DAG alone and not of the order in which edges were inserted, which is the
same schedule-independence property as Section~\ref{sec:determinism} and is checked by the same
gate. The reduction applies only to the causal graph; states, events and the branchial relation
are never reduced.

\subsection{Sampled Exploration}
\label{sec:sampling}

Exhaustive evolution is not always the object of interest, and the state count grows too quickly
for it to be available at large depth. The engine therefore admits sampling, applied at the
transition rather than at the state: each candidate transition is retained with a fixed
probability, so the number of children a state contributes remains a random variable rather than
being truncated to a fixed count. Truncating to a fixed count per state would collapse the
offspring distribution to a point mass and remove the property the sample exists to estimate.

Per-rule weights multiply that retention probability, so a rule may be explored fully while
another is suppressed entirely, and the two controls compose rather than one overriding the other.
A seed makes a sampled run reproducible; sampling decisions are keyed on canonical identity, so the
same seed yields the same sample at any thread count, consistent with
Section~\ref{sec:determinism}.

\subsection{Sessions}
\label{sec:sessions}

Evolution is also exposed as a session rather than only as a single call. A session is opened on a
rule set and initial condition, advanced by a requested number of steps, queried for any of the
derived structures, and closed. The unexplored frontier is retained between steps, so advancing a
session continues the existing exploration instead of recomputing it from the initial state, and a
caller may inspect intermediate results before deciding how much further to evolve.

\subsection{Event Canonicalization}
\label{sec:event-canon}

Events can be canonicalized at multiple granularities:

\begin{description}
\item[ByState:] Events with identical (input, output) state pairs are deduplicated. $\BigO(1)$ signature computation.

\item[ByStateAndEdges:] Events include consumed/produced edge positions, canonicalized via the state's vertex ordering. $\BigO(E)$ signature computation.

\item[None:] All events preserved. Required for complete causal graph reconstruction.
\end{description}

The choice affects both correctness (for certain analyses) and performance. ByStateAndEdges mode requires computing edge correspondences between isomorphic states, using the canonical state's vertex hash ordering.

\subsection{GPU Canonicalization}

The device does not reimplement canonicalization. The individualization--refinement body is a single source compiled for both host and device, so host and device compute the same canonical hash for a given state by construction, and the device applies it to every state under the exact mode. The color-refinement step shown below is IR's inner loop; it is vertex-parallel, and that is the property exploited on the device:

\begin{algorithm}
\caption{GPU WL Color Refinement (per thread block)}
\label{alg:gpu-wl}
\begin{algorithmic}[1]
\Procedure{GPUWLHash}{$\hypergraph$}
    \State Initialize $c_v \gets \deg(v)$ for all $v$ in parallel
    \Repeat
        \State \textbf{parallel for} each $v \in V$ \textbf{do}
        \State \quad $c_v' \gets \hash(c_v, \text{multiset}\{c_u : u \in N(v)\})$
        \State Swap $c \gets c'$
    \Until{coloring stable}
    \State \Return $\hash(\text{sorted}(\{c_v\}))$
\EndProcedure
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:gpu-wl} is not used as a state identity on the device. The device's canonical identity is the shared IR body of Section~\ref{sec:ir}; the only additional device-side hash is the content-ordered key required by \textsc{Automatic} identity, which applies the same rule as the host. A state whose canonicalization exceeds the pre-sized device scratch is reported as a truncation and retried with a larger arena; it is not silently replaced by a coarser identity.

\subsection{GPU Pattern Matching}

Signature-based candidate generation parallelizes across warps:

\begin{itemize}
    \item Each warp processes one pattern edge
    \item Threads within warp enumerate compatible signatures (up to $B_d$ per edge)
    \item Atomic queue updates coordinate task creation
    \item Lock-free state insertion handles deduplication
\end{itemize}

\subsection{Memory Management}

GPU memory is managed through:
\begin{itemize}
    \item Pre-allocated edge/state pools with atomic counters
    \item Unified memory for large hypergraphs (automatic CPU-GPU migration)
    \item Shared memory for thread block-local data structures
\end{itemize}

\section{Conclusion and Future Work}
\label{sec:conclusion}

We have presented an implementation of multiway hypergraph evolution built on exact canonicalization and lock-free concurrency. Compared with the Wolfram \texttt{MultiwaySystem} implementation on the same rule and initial condition, and producing identical state and causal-edge counts at every depth, the engine is faster by factors of $5{,}507$, $12{,}589$, $27{,}108$ and $45{,}713$ at depths four through seven respectively (Table~\ref{tab:t2-speedup}); the ratio increases with depth over the range measured. On the host, evolution attains a speedup of $12.8\times$ on this machine's 24 physical cores, with parallel efficiency higher on the larger of the two problem sizes (Table~\ref{tab:t8-scaling}). Efficiency remains at or above $0.78$ up to eight workers and at or above $0.82$ up to sixteen, depending on the rule's shape, and declines beyond that (Table~\ref{tab:t12-shapes}); the measured cause is memory acquisition rather than contention, since user time increases by a factor of $2.1$ across a $32\times$ increase in worker count while system time increases by a factor of $206$ and tracks the per-worker resident set and minor-fault count (Table~\ref{tab:t13-memory}). On the device, wall time ceases to improve beyond eight blocks per streaming multiprocessor (Table~\ref{tab:t11-saturation}). The GPU is slower than eight CPU threads at depth five and $12.4\times$ faster at depth seven (Table~\ref{tab:t7-gpu}). The contributions are:

\begin{enumerate}
    \item Exact canonicalization via individualization--refinement (IR) computed on every state, its hash serving directly as the deduplication key, validated against a brute-force isomorphism oracle
    \item Lock-free concurrent data structures enabling efficient multi-threaded evolution
    \item A GPU evolution backend for pattern matching and canonicalization
    \item Independent, exact state and event equivalencing axes with configurable granularity
    \item Quotient exploration, transition-level sampling, and an online transitive reduction of the causal graph, each preserving the observable contract of Section~\ref{sec:determinism}
\end{enumerate}

\subsection{Future Directions}

Several avenues remain for further optimization:

\textbf{Incremental pattern matching:} Currently, pattern matching restarts for each state. Maintaining match validity across evolution could provide a substantial additional speedup for deep evolutions.

\textbf{Distributed computation:} The current design targets single-node execution. Extending to distributed memory systems would enable exploration of vastly larger state spaces.

\textbf{Rule learning:} Automatic discovery of rules producing desired structures (e.g., emergent dimensionality, causal invariants) remains an open challenge amenable to learned heuristics.

\textbf{Formal verification:} Proving correctness of the lock-free algorithms under relaxed memory models would strengthen confidence in the implementation.

\subsection{Availability}

The engine is used both directly as a library and as the evolution backend for downstream tools,
including interactive visualisation of evolution, causal and branchial graphs. The implementation
is available as:
\begin{itemize}
    \item Source code: \url{https://github.com/PLACEHOLDER/efficient-rewriting}
    \item Wolfram Language paclet: \url{https://resources.wolframcloud.com/PacletRepository/resources/PLACEHOLDER}
\end{itemize}

\section{Complexity Analysis Details}
\label{app:complexity}

\subsection{Canonicalization Complexity}

For a hypergraph with $|V|$ vertices and $|E|$ hyperedges of maximum arity $k$, the two canonicalization roles have very different cost profiles.

\textbf{Weisfeiler--Leman signature.} One refinement round aggregates, for each vertex, the multiset of neighbor colors: $\BigO(k \cdot |E|)$ work per round, with at most $|V|$ rounds before the coloring stabilizes, giving $\BigO(|V| \cdot k \cdot |E|)$ in the worst case and far less in practice (the partition typically stabilizes in a few rounds). WL is a sound but incomplete invariant: identical hashes are necessary but not sufficient for isomorphism.

\textbf{Individualization--refinement (exact).} IR interleaves color refinement with individualization of vertices in non-singleton cells, exploring a search tree pruned by discovered automorphisms. It is polynomial on instances that refinement alone resolves, but---like nauty and Traces---exponential in the worst case, with the blow-up concentrated on highly symmetric (high-automorphism) states. We claim no polynomial-time bound. Under the exact mode IR is applied to every state, and profiling attributes approximately half of the engine's executed instructions to it. Bucketing by a cheaper hash and invoking IR only on collisions does not reduce this cost, by Proposition~\ref{prop:wlceiling}: a repeated bucket is consistent with a genuine duplicate, which IR must still confirm, so such a filter elides at most a fraction $C/R$ of the invocations it precedes.

\subsection{Pattern Matching Complexity}

For pattern with $|L|$ edges and state with $|S|$ edges:

\begin{itemize}
    \item Signature index lookup: $\BigO(1)$ per pattern edge
    \item Candidate enumeration: $\BigO(|S|/B_d)$ expected where $B_d$ is the Bell number
    \item Match verification: $\BigO(|L|)$ per candidate
    \item Total: $\BigO(|L| \cdot |S| / B_d \cdot |L|) = \BigO(|L|^2 \cdot |S| / B_d)$
\end{itemize}
