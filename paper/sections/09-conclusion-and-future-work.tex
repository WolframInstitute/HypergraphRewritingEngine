\section{Conclusion and Future Work}
\label{sec:conclusion}

We have presented an implementation of multiway hypergraph evolution built on exact canonicalization and lock-free concurrency. Compared with the \texttt{Wolfram/\allowbreak Multicomputation} paclet's \texttt{MultiwaySystem} on the same rule and initial condition, and producing identical state and causal-edge counts at every depth, the engine is faster by a factor of $\SpeedupAtLowDepth$ at depth \SpeedupLowDepth{}, rising to $\SpeedupAtHighDepth$ at depth \SpeedupHighDepth{} (Table~\ref{tab:t2-speedup}). The ratio rises monotonically across those four depths. At the shallow end of the range the engine's own time is a fraction of a millisecond, close enough to the timer's resolution that those ratios are better read as lower bounds on the gap than as exact factors; at depth \SpeedupHighDepth{} it is $\CoreDeepMs$\,ms against $\AuthorityDeepSeconds$\,s, so that row is a direct measurement on both sides. The same table carries \texttt{MultiwayReference}, this project's own brute-force evolver of the same definition, as the correctness oracle: all three agree on state and causal-edge counts at every depth. It also isolates what the Wolfram layer itself costs: the engine reached through the paclet---WXF serialization over the wire and Wolfram structures built on return---delivers the identical answer at depth \SpeedupHighDepth{} in $\PacletDeepSeconds$\,s against the core's $\CoreDeepMs$\,ms, a factor of $\PacletOverheadDeep\times$ spent entirely in the layer, and still $\PacletVsAuthorityDeep\times$ ahead of the authority, which pays for the same layer. On the host, evolution attains a speedup of $\MaxHostSpeedup\times$ at \MaxHostSpeedupThreads{} worker threads, with wall time falling at every step of the sweep (Table~\ref{tab:t8-scaling}). Efficiency remains at or above $\EffAtEight$ up to eight workers and at or above $\EffAtSixteen$ up to sixteen, depending on the rule's shape, and declines beyond that (Table~\ref{tab:t12-shapes}). The measured cause is cross-domain data flow, not contention and not memory acquisition: across a $\ThreadSweepFactor\times$ increase in worker count the instruction count stays flat while instructions per cycle falls from $1.44$ to $0.69$, the growing hardware counter is fills served from another L3 domain's cache---the evolution's own producer-to-consumer traffic, with the concurrent structures excluded by direct experiment---and user time grows by $\UserTimeGrowth\times$ against a kernel-side term (system time by $\SysTimeGrowth\times$, tracking the fault count) that stays below three per cent of the total (Table~\ref{tab:t13-memory}). On the device, wall time ceases to improve beyond \SaturationBlocks{} blocks per streaming multiprocessor (Table~\ref{tab:t11-saturation}), and the GPU is $\GpuSpeedupAtDeepest\times$ faster than eight CPU threads at depth \GpuDeepestDepth{} (Table~\ref{tab:t7-gpu}). The contributions are:

\begin{enumerate}
    \item Exact canonicalization via individualization--refinement (IR) computed on every state, its hash serving directly as the deduplication key, validated against a brute-force isomorphism oracle
    \item Lock-free concurrent data structures, whose properties are model-checked rather than
stress-tested (Section~\ref{sec:verification})
    \item A resident CUDA kernel that carries matching, rewriting and canonicalization without
returning to the host between evolution steps
    \item Independent, exact state and event equivalencing axes with configurable granularity
    \item Quotient exploration, transition-level sampling, and an online transitive reduction of the causal graph, each preserving the observable contract of Section~\ref{sec:determinism}
    \item A determinism contract: the state set, event set and causal and branchial relations are a function of the inputs alone, independent of thread count and scheduling order (Section~\ref{sec:determinism})
\end{enumerate}

\subsection{Future Directions}

Three directions remain open, all of scope.

\textbf{Distributed computation:} The current design targets single-node execution. Extending to distributed memory systems would enable exploration of larger state spaces than one machine's memory admits.

\textbf{Rule learning:} Automatic discovery of rules producing desired structures (e.g., emergent dimensionality, causal invariants) remains an open challenge amenable to learned heuristics.

\textbf{Verification beyond the bound:} The properties of Section~\ref{sec:verification} are
established for bounded programs under RC11 and, for the forwarding protocol, over an unbounded
worker count against a transcribed model. Neither establishes the code's properties for unbounded
thread counts. A mechanised proof over the implementation itself would.

\subsection{Availability}

The engine is used directly as a library and as the evolution backend for downstream tools; with
\texttt{BUILD\_VISUALIZATION} enabled it emits an event stream that an external renderer consumes
to draw the evolution, causal and branchial graphs. The implementation is available as:
\begin{itemize}
    \item Source code: \url{https://github.com/WolframInstitute/HypergraphRewritingEngine}
    \item Wolfram Language paclet: \texttt{WolframInstitute/}\allowbreak\texttt{HypergraphRewriteEngine},
          installable with
          \texttt{PacletInstall[}\allowbreak\texttt{"WolframInstitute/}\allowbreak\texttt{HypergraphRewriteEngine"]}
\end{itemize}
