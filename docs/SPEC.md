# SPEC — the formal reference of the engine's functionality

*What the engine computes, stated precisely and independently of how it is implemented. The
implementation is reviewed against this document; the user documentation derives from it; every
claim in it is held by a named gate in the test suite. Where the reference implementation
(`reference/MultiwayReference.wl`) or the Wolfram `MultiwaySystem` fixes a convention, this spec
records it.*

---

## 1. Objects

- **Vertex.** An opaque identity. Vertices are only ever created or shared, never independently
  destroyed (see §2).
- **Hyperedge.** An ordered tuple of vertices (arity ≥ 1; within-edge order is significant).
- **Hypergraph / state.** A finite multiset of hyperedges. Multiplicity is significant. A vertex
  "exists" in a state iff some edge references it — there is no separate vertex set.
- **Rule.** A span `L ←l— K —r→ R` of hypergraphs: `L` the left pattern, `R` the right pattern,
  `K` the interface (the shared/preserved part). Concretely a rule is `(LHS edge-patterns, RHS
  edge-patterns)`; variables occurring in both sides are `K` (preserved), LHS-only variables are
  consumed context, RHS-only variables are freshly created.
- **Match.** A homomorphism `m : L → G` (see §3 for the admitted class).
- **Event.** One rule application: `(input state, rule, matched edges, produced edges, output
  state, step)`.
- **Multiway system.** The transition system over states generated by applying every match of
  every rule, together with its **causal** and **branchial** relations over events (§5).

## 2. Rewrite semantics (DPO on the edge-replacement fragment)

An event with match `m` of rule `L←K→R` at state `G` produces `G'` by:

1. **Consume** the matched hyperedges (`m(L\K)` — i.e. the LHS edges).
2. **Preserve** everything else in `G`, including all vertices.
3. **Produce** the RHS edges, allocating a fresh vertex for each RHS-only variable and reusing
   the matched vertex for each preserved variable.

**Deletion is restricted to hyperedges; vertices are never deleted.** Therefore the DPO **gluing
conditions hold for every match**: the identification condition holds because a match identifies
only vertices (it is edge-injective, §3) and a rule preserves every vertex of its left side; the
dangling condition triggers only on vertex deletion, and no vertex is ever deleted. On this
fragment **DPO and SPO coincide** — the two calculi differ only on
vertex-deletion-with-danglers, which the rule format cannot express. The interface `K` is exactly
the preserved-vertex set. No match is ever rejected at application.

*(Verified in `hypergraph/src/rewriter.cpp`: the child edge set is `derive(input, consumed) +
produced`; vertices are only allocated or reused; there is no vertex deletion anywhere. The
totality argument is restated at the matcher's shared core, `common/include/hgcommon/join_core.hpp`.)*

## 3. Matching

A match is a homomorphism `m : L → G` required to be:

- **arity-preserving** — a pattern edge maps to a host edge of equal arity;
- **repetition-consistent** — a variable occurring in several positions maps to a single vertex;
- **edge-injective** — distinct pattern edges map to distinct host edges.

It is **not** required to be vertex-injective: distinct pattern variables **may** bind the same
host vertex (variable folding), following the Wolfram-model convention. Because deletion never
reaches vertices (§2), the identification condition raises no hazard.

*(Verified in `common/include/hgcommon/join_core.hpp` — one shared body for both engines: binding
on first occurrence, equality on repeat, edge-injectivity on the join's frontier.)*

## 4. Canonicalization — two axes

State identity and event identity are chosen independently: any state mode combines with any
event mode, and every observable of §5 is well-defined in every cell. The gate for the whole
surface is `RelationCoherence` (`paclet_source/tests/test_wxf_serialization.cpp`), which sweeps
state mode × event mode × quotient × transitive reduction on **both** engines.

### 4.1 State identity — `CanonicalizeStates`

Which states are the same node.

| value | two states are one node iff | dedup key |
|---|---|---|
| `None` (default) | never — every raw state is its own node | the state's own id |
| `Automatic` | their edge lists are identical, edges in creation order and vertices by their labels (**not** isomorphism-invariant) | content-ordered hash, with the content words compared on a key hit |
| `Full` | they are isomorphic as ordered hypergraphs (vertex relabeling; within-edge order and multiplicity preserved) | the canonical hash, with the canonical forms compared on a key hit |

The canonical form is McKay-style individualization–refinement (IR). The **reported** per-state
canonical hash (`IncludeCanonicalHashes`) is this invariant in every state mode — stored at creation
when event canonicalization is on (one IR pass serves both the hash and the per-edge ranks of
§4.2), computed on first query otherwise. Under `Full`, a class whose hash key is already held by a
non-isomorphic class takes the next probe key (`hgcommon::dedup_probe_key`), and that key is the
hash it reports; which of two colliding classes keeps the unmodified hash depends on arrival order,
while the state set and every count do not.
*(`hypergraph.cpp`, `compute_canonical_hash`, `claim_canonical_state`; gates:
`OracleCorpus.CanonicalKeyCollisionsKeepStateIdentityExact` runs the corpus with the key narrowed
to two bits, and `mode_matrix_probe` reads identical event counts down every state-mode column.)*

### 4.2 Event identity — `CanonicalizeEvents`

Which applications are the same event. An event signature is composed from a subset of six
components, each isomorphism-invariant and computable by both engines: the canonical input-state
hash, the canonical output-state hash, the step, the rule index, and the canonical **ranks** of
the consumed and produced edges (a rank is the position an edge takes in its own state's
canonical labeling; consumed ranks are taken in match order, produced ranks in RHS order).
*(`common/include/hgcommon/event_core.hpp`, one body for both engines.)* Two applications are one
event when their signature VALUES are equal: the 64-bit signature selects the key, a key hit
compares the values, and a class whose key another class holds takes the next probe key, as for
states (§4.1). The class's key is the signature reported.

| value | signature components | meaning |
|---|---|---|
| `None` (default) | none — no signature is computed | every application is its own event |
| `Full` | input hash, output hash | identity = the (canonical input, canonical output) pair |
| `Automatic` | input hash, output hash, step, consumed ranks, produced ranks | also distinguishes *which* edges moved and *when* |
| `Positional` | as `Automatic` | ranks read from each raw state's **own** labeling rather than the class frame — the upstream parity mode, below |
| `{keys…}` | any subset of `"InputState"`, `"OutputState"`, `"Step"`, `"Rule"`, `"ConsumedEdges"`, `"ProducedEdges"` | a custom point of the lattice |

`"Step"` is the event's own step, the step of the raw state it produces (`hgcommon::qr_out_step`),
on both engines and both routes.

In a key list, `"ConsumedEdges"` is the canonical hash of the input state with the consumed edges
marked, and `"ProducedEdges"` that of the output state with the produced edges marked
(`hgcommon::ir_colour_pad`; `reference/MultiwayReference.wl` `eventSigAutomaticCanonical`). A
marked edge of arity k is extended to arity 17 by an added vertex, so the hash is a complete
invariant of the state with its marked edges. A key list counts the same events under full capture
and quotient exploration at any thread count (`OracleCorpus.CustomEventKeySetsAgreeAcrossRoutesAndThreads`).
The GPU engine serves `None`, `Full` and `Automatic`; a key list runs on the CPU engine with an
`Engine` warning (`GpuBinaryGate.ACustomEventKeySetRunsOnTheCpuEngine`).

**`Automatic` is the linked-hypergraph convention**: ranks are resolved in the canonical frame of
the state's isomorphism class, so the identity is a property of the event and not of the schedule
or presentation that produced it. It is adjudicated step-exact against the authoritative
`Wolfram/Multicomputation` `MultiwaySystem` (`reference/adjudicate_gap1_authority.wls`). Its
class-frame resolution is defined over edge-orbit tables, which the `Full` state mode computes;
under `None`/`Automatic` state modes the engine computes event identities exactly (§4.1) but
resolves ranks through the raw path, and says so in a run warning.

**Which labelling gives the ranks.** On a state with a nontrivial automorphism group the
canonical labelling is one of several, and the IR search picks it with a tie-break that reads
the state's vertex numbering. Both engines number a state's vertices in order of first
appearance, reading its edges in the state's order (the parent's surviving edges in the
parent's order, then the produced edges in right-side order) and each edge's positions in
order (`hgcommon::ir_renumber_encounter`). The numbering is a function of the state's
derivation, so the ranks are the same at every worker count and on both devices.
`MultiwaySystem` breaks the same ties on its own token and vertex names: a produced edge takes
the token of the edge it replaces, and fresh vertices are named in its evaluation order. No
numbering of the engine's state reproduces those names: `{{1,1}} -> {{1,2}}` from
`{{1,1},{1,1}}` gives 4 `MultiwaySystem` `Automatic` events at 2 steps and 3 on both engines,
because its two step-2 events differ only in those names (`reference/compare_multiwaysystem.wls
--engine` lists the counts on its corpus).

**`Positional` reproduces the upstream `MultiwaySystem` `Automatic` convention**, and is retained
as an explicitly-labeled parity mode — never described as canonical. Upstream identifies events
by *which representative isomorphism* the state canonicalizer returned, and that canonicalizer
selects its representative by WL's stable sort among automorphic labelings — a function of
incidental input edge order, not of the isomorphism class. So `Positional` identity is
`Sort[]`-tie-break-defined: reproducible for a fixed WL build and input order, but not a
mathematical invariant. It is incompatible with quotient exploration (which materialises no raw
presentations); requesting both runs full capture and reports the disabled optimisation.

**When a rank is unavailable** (no rank table for a state), the raw edge id stands in and the
substitution is **counted** — such a signature is not an isomorphism invariant, and a caller
comparing event counts across runs needs to know it happened. The device surfaces the count as an
`EventSigRawFallback` warning.

## 5. Observable contract

The engine's observable output is a **deterministic, schedule-independent function of `(rules,
initial states, steps, options)`** — the same for 1 or N threads, quotient on or off — for every
exact configuration. Sampling and capping options refine this as follows:

- **`TransitionRate`** (with `RuleWeights`) keeps each transition with the given probability,
  drawn from the transition's isomorphism-invariant identity and the seed — so the sampled
  subgraph is the same at every worker count and on either device, and reproducible for a fixed
  `RandomSeed`. A spine keeps the state's transitions with the smallest seeded rank when none of
  its draws passed, so a fixed rate below the branching factor thins rather than extinguishes. A
  run under it matches every state in full (match forwarding off), so the draw and the spine see
  all of the state's transitions.
- **`ExplorationProbability`** samples **per canonical state**, keyed the same way.
- **`MatchesPerStateRule`** caps each state's transitions per rule, chosen at the state's drain
  by the same invariant key — schedule-independent. A run under it matches every state in full
  (match forwarding off), so the drain chooses from all of the state's matches.
- **`MaxSuccessorStatesPerParent`** keeps the transitions out of a state into its k lowest-ranked
  successor states, chosen at the state's drain; **`MaxStatesPerStep`** keeps the transitions of a
  step into the step's N lowest-ranked successor states, chosen once the step's matching is
  complete. The depth join signals that completion and submits the choice as a task; no worker
  waits on a barrier for it. Both count distinct successor STATES under the state identity in force (§4.1):
  under `None` every transition makes its own state, so both count transitions; under
  `Automatic` two transitions make one state when the edge lists of the states they make are
  identical (a transition that creates a vertex makes its own state); under `Full` when those
  states are isomorphic. A successor's rank is the smallest rank among the transitions into it,
  and every transition into a kept successor is kept (`hgcommon::SuccessorIdentity`,
  `hgcommon::successor_ranks`). Successors are told apart by their 64-bit identity hash (the
  content hash under `Automatic`, the canonical hash under `Full`), computed before the rewrite
  runs (`hgcommon::SuccessorCursor`). **`MatchesPerStep`** (with `UniformRandom -> True`)
  replaces `MaxStatesPerStep` and keeps N transitions of a step, drawn uniformly without
  replacement: the step's transitions are ordered by (group, key), the seed and the step draw N
  positions in that order (`hgcommon::step_positions`), and the transitions at those positions
  are kept, each with every transition of equal (group, key). Under `None` states the key is the
  transition's lineage key and the group its state's lineage label (below); under `Automatic`
  and `Full` states the key is the transition key and the group 0. With `MatchesPerStep -> 1`
  each step applies one transition to one state, so the run is a single history. All three are
  schedule-independent, and a transition not kept is not taken (no event, no state).
- **The step in a step cap.** Under `MaxStatesPerStep` and `MatchesPerStep` every state is
  matched at one step, and every rank and every draw of positions mixes in the step of the
  events the transitions make (`hgcommon::rank_step`). A history that returns to an isomorphic
  state chooses again there instead of repeating its earlier choice.
- **Lineage labels.** Under `None` states with `MatchesPerStep` every edge and state carries a
  64-bit label fixed when it is made (`hgcommon::lineage_*`). An initial state's label is a hash
  of its canonical hash, and its edges' labels hash that label with each edge's canonical rank.
  A transition's lineage key hashes the rule and the matched edges' labels in pattern order. A
  rewrite labels its produced edges by that key and their right-hand-side positions, and the
  state it makes by its input state's label and that key. A transition's key and its position
  in a state's order stay fixed while the state's later rewrites leave its edges in place, and
  the labels are a function of the inputs, so the selection is the same at every worker count
  and on both devices.
- **The key.** A transition's key is the input state's canonical hash, the rule, and one
  coordinate per matched edge: under `Full` states the edge's automorphism orbit, otherwise its
  canonical rank (`canonical_transition_key`, `transition_key_device`). Under `Full` states
  automorphic transitions share the key, so every draw, cap and spine keeps a set that the
  state's automorphisms map onto itself, and the quotient reconstruction (§5.4) replays the same
  set onto every raw state of the class.
- **Ties at a cap's cut are kept.** Every cap (per rule, per state, per step) keeps all the
  transitions, or successor states, tied with the k-th kept one (`hgcommon::cap_keep_count`,
  `hgcommon::rank_cut`), so the kept set does not depend on list order.
- **`StateCost`** orders the successors of a step cap (`MaxStatesPerStep`, or `MatchesPerStep`)
  by cost. The cost of a state is a function of its `"Invariants"` statistics (the per-state
  values `"StepStatistics"` summarises), given as a pure function such as
  `Abs[#BallDimension - 3] &`. The step keeps the transitions into its N successors of lowest
  cost, and the successor rank orders successors of equal cost. A successor's cost is computed
  from its IR canonical form, so isomorphic successors have one cost and the kept set is a
  function of the inputs alone. The cost is an IEEE double computed by one interpreter on both
  devices (`hgcommon::state_cost_eval`; products through `dm_mul`, logarithms, exponentials and
  non-integer powers through `det_math.hpp`). A state that has no value for a statistic the
  cost reads (for example `"BallDimension"` of a state with no ball-growth fit), or whose cost
  is NaN, has cost +Infinity and ranks after every state with a finite cost. The cost applies
  under every `CanonicalizeStates` mode: under `None` and `Automatic` each transition's
  successor is canonicalised for its cost only, and the identity in force still decides which
  successors are distinct. `MaxSuccessorStatesPerParent` and `MatchesPerStateRule` are not
  guided by the cost; they bound the candidates a step's cost is computed for.
- **List order.** `"CausalEdges"` and `"BranchialEdges"` list their rows in ascending order
  (`hgmarshal::relation_list`), so a list's order is a function of its pairs.
- **A truncated run.** A run that reaches a container ceiling, or whose allocation fails, stops:
  the task that failed ends, the queued tasks are dropped unrun, and the states, events and
  relations already published are the result, with a warning marked `"Partial" -> 1`
  (`HGEvolve::overflow`). The host engine holds 256 MB of untouched address space during a run
  and gives it back when an allocation fails (`AddressReserve`), for the reply. A reply that
  does not fit the memory left carries the counts and the warnings, `"Reduced" -> 1`, and
  `HGEvolve` gives empty lists for the rest.

*(Gates: `SamplingReproducibility.*` — same states at every worker count, reproducible per seed;
`CausalDeterminism.*` at 1–32 threads.)*

### 5.1 States and events

The state set under §4.1, the event set under §4.2. Counts and lists agree with the structures
built from them by construction (§5.2's one-relation rule).

Raw ids are not part of the observable output. States, events and edges are numbered in the order
the workers create them, so two identical runs can give the same states under different raw ids
and return lists in a different order. The observable output is the counts, each state's
contents, the canonical hashes (`IncludeCanonicalHashes`), and the graphs up to a renaming of
their vertices. Within one reply the ids are consistent: under `CanonicalizeStates -> Full`,
`"States"` is keyed by each class's canonical state id, and an event's `"CanonicalInputState"` and
`"CanonicalOutputState"` are keys of `"States"`.

### 5.2 Causal relation

An edge instance carries the identity of the event that produced it (its **producer**); an
initial edge's producer is its root's genesis event. There is a causal pair `p → c` whenever
event `c` **consumes an edge that event `p` produced**. `ShowGenesisEvents` (default off) decides
whether pairs involving genesis events are part of the observable relation. With it, each initial
state has one genesis event (`"RuleIndex"` 65535), its own event under every event identity and
counted in `NumEvents`, and a pair `g → c` for
every event `c` that consumed an edge of `g`'s initial state (under `CausalTransitiveReduction`,
only those that consumed no produced edge); its input state is not one of `"States"`. Both
exploration routes give the same events and pairs. Under full capture the CPU engine reports a
genesis event under its own event id; on the reconstruction route (§5.4) and on the GPU engine,
the genesis event of the i-th initial state is reported under 2^32 + i and the GPU engine's
genesis state under 2^32 (`hgmarshal::genesis_event_id`). Every engine id is below 2^32, and a
session's Steps leave these ids unchanged, so `"Delivery" -> "Delta"` serves the genesis events
as increments.

**Transitive reduction (`CausalTransitiveReduction`, default on)** applies to the causal relation
*only* (never states, events, or branchial), and removes a pair `p → c` when a longer directed
path `p ⇝ c` exists. The reduction of a DAG is unique, so the reduced relation is a function of
the relation and not of the insertion schedule. Under full capture a redundant pair is dropped at
registration; under the reconstruction (§5.4) the replay decides it as each event's producers
are recorded, over all of them at once (`hgcommon::redundant_producers`); the relation between
canonical event ids, served when the replay is off, is reduced on read (`hgcommon::tr_reduce`). *(Gate: order-independence at 1–16 threads,
`causal_tr_exactness_probe`; both mechanisms measure ALL EXACT.)*

**One relation.** The causal relation reaches a caller in three shapes, and they are the same
relation with `CausalTransitiveReduction` applied: `NumCausalEdges` is its size, `CausalEdges` is
its pairs (endpoints annotated with the §4.2 identity and the raw application id), and the causal
graph properties are its identity-projected view — vertices are events under the identity in
force (every application its own vertex under `None`), and `EdgeDeduplication` (default on)
serves one edge per identified pair. *(Gate: `RelationCoherence`, both engines, every cell,
including a workload whose raw DAG has bypassed pairs so the reduction visibly bites.)*

### 5.3 Branchial relation

Two events are branchially related iff they **share the same input state and consumed a common
edge instance**. Computed on the raw event structure; independent of the event-identity choice;
no reduction applies. The relation has one edge per event pair, however many edges the two
events both consumed, and the branchial state graph has one edge per event pair between their
output states; `EdgeDeduplication` does not apply to it. `BranchialEdges` and the branchial
graphs follow §5.2's one-relation rule.

### 5.4 Quotient exploration and reconstruction

`ExploreFromCanonicalStatesOnly` (default off) expands each **canonical** state once, at its
shortest depth, rather than once per raw isomorphic copy — the expensive work (matching,
canonicalization) is paid O(canonical states) times instead of O(raw states). It requires `Full`
state canonicalization (its machinery is defined over canonical classes and their edge orbits)
and is refused with a warning otherwise. It is also refused with a warning (`QuotientStepCap`)
under `MaxStatesPerStep` and `MatchesPerStep`: a step cap chooses among the transitions of a step,
and quotient exploration expands one raw state per class, at the class's shortest depth only.
**It is a performance mode, never a semantic one.**

A class reached first along a longer path has its depth lowered when a shorter path arrives
(`hgcommon::explore_try_lower`). A lowering is at most the step budget less one, and no smaller
bound holds for every schedule, since the shorter path's rewrite can run last. The largest
lowering measured over the oracle corpus is 2 (`OracleCorpus.DepthLoweringIsBoundedByTheStepBudget`).
So no depth is complete before the run is, and a run under quotient exploration gives no
per-depth completion signal.

**Contract: every observable under quotient equals the same observable under full capture, in the
same cell** — states, events, causal (count, list, graph), branchial, and the reduction — on the
full input classification including cyclic (recurrent) rules. The raw quantities the compressed
skeleton does not explore are recovered by an online, lock-free, non-phasic reconstruction: each
class retains its representative's expansion as slot-named matches, and raw instances are
replayed forward over the depth-unrolled skeleton, minting one raw event per (instance, match)
claim. The replay is off the scheduler's critical path. Under `MaxStatesPerStep` (full capture
with Automatic event identity) a class keeps different transitions at different depths, so each
(class, depth) retains its own expansion, captured from a raw state at that depth
(`hgcommon::qc_expansion_key`).

*(Gates: `cost_matrix` — oracle-exact on every corpus row, states/events/causal/branchial;
`RelationCoherence.QuotientServesFullCapturesNumbers`; `QuotientReconstruction.*` including a
depth that saturates the device pools; the brute-force oracle is `reference/MultiwayReference.wl`,
cross-checked against the authoritative `MultiwaySystem`.)*

**Class multiplicities.** A class c at depth d stands for m(c, d) raw states: m(root, 0) = 1 and
m(c', d + 1) is the sum of m(c, d) over the matches of c whose output is c'. It equals the
number of raw states of class c at step d of the unfolding. When a request reads the raw events
and branchial pairs only as `NumEvents` and `NumBranchialEdges`, they are computed from the
multiplicities and no raw instance is replayed: the raw events are the sum of m(c, d) M(c) over
d < steps, M(c) the class's matches, and the branchial pairs the sum of m(c, d) B(c), B(c) its
pairs of matches with overlapping consumed edges. Counts above 2^63 - 1 report 2^63 - 1; a
requested count that does so gives the warning `CountSaturated` naming it. *(Gates:
`OracleCorpus.MultiplicityCountsMatchTheReplay`, `WxfSerializationPin.ACountSaturatedWarningNamesARequestedCount`,
`OracleCorpus.ClassMultiplicitiesCountTheRawStates`, `RecordSet.ClassMultiplicitiesMatchTheHost`.)*

**Replay ids.** The replay's raw event and instance ids are 32-bit and minted below
`hgcommon::QR_ID_LIMIT` (2^32 - 2^20). An application past the limit is dropped and the run
reports the partial warning `ReplayIdsExhausted`, with the number dropped on the host. *(Gates:
`OracleCorpus.ReplayIdLimitTruncatesAndReports`, `QuotientReconstruction.ReplayIdLimitTruncatesAndReports`.)*

**Unaligned captures.** A captured transition whose edges have no image in its class's frame
cannot be replayed and is dropped; the run reports the partial warning `CapturesDropped` with the
number of captures. No input is known to reach it.

**`StepStatistics`.** Per step, the population of raw states at that step: `RawStates`, `Classes`,
`Redundancy`, `MaxMultiplicity`, `MultiplicityHistogram`, `ClassEntropyBits`,
`ClassEntropyNormalized`, `Events` and `RuleCounts` (raw events whose output state is at the
step), `Invariants` (summaries of per-state invariants: `N`, `Mean`, `StandardDeviation`, `Min`,
`Max`, `Median`, `Histogram`) and the pooled arity and degree histograms. Every invariant is an
isomorphism invariant, so each step is summarised from one state per class weighted by m(c, d);
under full capture every raw state counts once. The largest incidence component is the one with
the most nodes, then the greatest diameter, then the greatest mean distance, then the most
vertices. *(Gate: `reference/verify_state_statistics.wls`, against the definitions computed in
Wolfram Language from a raw run.)*

With `"StepStatisticsWeighting" -> "Classes"` each class at a step counts once in `Invariants`,
`BallGrowthDimension`, `LogGeodesicCount` and the pooled histograms; `RawStates`, `Classes`, the multiplicities,
the class entropy, `Events` and `RuleCounts` are unchanged. The default `"States"` counts each
class m(c, d) times.

**`StepStatistics` geometry.** Fourteen more `Invariants` entries, each an isomorphism invariant of
a state, computed by `common/include/hgcommon/state_geometry_core.hpp`. A state's graph G is
the undirected simple graph on the state's vertices whose edges join the vertices of each
hyperedge by the rule of the option `"StatisticsGraph"`. Under `"Consecutive"`, the default,
the consecutive vertices of each hyperedge are joined ({a, b, c} gives a-b and b-c). Under
`"AllPairs"` every two vertices of a hyperedge are joined ({a, b, c} gives a-b, a-c and b-c).
Self-loops are dropped and a repeated pair is one edge. Both rules give the same components, and
the same graph for a state whose hyperedges have at most two vertices. Every value of this
section and of the sections after it that reads G uses the chosen rule, on both devices, and
so does `VertexCurvature`. B(v, r) is the set of vertices at distance at most r from v, so
|B(v, 0)| = 1, and R is the graph radius of G. `"AllPairs"` is the graph of the Infrageometry
paclet's InfraSubstrate (Infrageometry@ffa5fe4:InfraGeometry/Kernel/InfraSubstrates/InfraSubstrate.wl:108, ResourceFunction["HypergraphToGraph"], the distance-preserving method of
SetReplace's HypergraphToGraph.m). A state for which a value is undefined is left
out of that entry's summary, so its `N` counts the states where it is defined.

| Entry | Definition | Undefined when |
|---|---|---|
| `GraphRadius` | the least eccentricity of a vertex of G (an integer number of edges) | G is empty or disconnected |
| `MeanEccentricity` | the mean over vertices of the eccentricity | as `GraphRadius` |
| `WolframHausdorffDimension` | the mean over vertices v of the mean over r = 1..R of (log\|B(v,r)\| - log\|B(v,r-1)\|) / (log(r+1) - log r); ResourceFunction["WolframHausdorffDimension"][G, All, "VertexMethod" -> Mean] | G is disconnected or has fewer than 2 vertices |
| `WolframRicciCurvatureScalar` | with d the state's `WolframHausdorffDimension`, the mean over vertices v of the mean over r = 1..R of 6(d+2)/r^2 (1 - \|B(v,r)\| Γ(d/2+1) / (π^(d/2) r^d)); ResourceFunction["WolframRicciCurvatureScalar"][G, d, All, "VertexMethod" -> Mean] | as `WolframHausdorffDimension` |
| `OllivierRicciCurvature` | the mean over edges x-y of G of 1 - W1(m_x, m_y), where m_x puts 1/2 on x and 1/(2 deg x) on each neighbour of x, and W1 is the optimal transport cost under the graph distance | G has no edge |
| `DegreeEntropy` | the Shannon entropy in bits of the distribution of vertex degrees in G | G is empty |
| `LocalEntropy` | the mean over vertices v of the entropy in bits of the degrees of the vertices in B(v, 2) | G is empty |

The per-step key `BallGrowthDimension` maps each radius r to the summary, over the states with
R >= r, of the mean over vertices v of (log\|B(v,r)\| - log\|B(v,r-1)\|) / (log(r+1) - log r):
ResourceFunction["WolframHausdorffDimension"][G, All, R, "DimensionMethod" -> Identity,
"VertexMethod" -> Mean]. Dimensions and entropies are dimensionless; curvatures are in units of
inverse edge length squared (`WolframRicciCurvatureScalar`) or dimensionless
(`OllivierRicciCurvature`).

The per-step key `VertexInvariants` pools the vertices of every state at the step, each state
weighted as in `Invariants`, into three distributions: `LocalDimension` (d_v over G'),
`OllivierRicciCurvature` (k_v over the vertices of G with a neighbour) and
`WolframRicciCurvatureScalar` (K_v over G', the mean over r = 1..R' of 6(D+2)/r^2
(1 - \|B(v,r)\| Γ(D/2+1) / (π^(D/2) r^D)) with D the state's `LargestComponentDimension`).
Each has `N`, `Mean`, `StandardDeviation` (N - 1), `Min`, `Max`, `Median`, `Q1`, `Q3`, `P10`,
`P90`, `Skewness` (m3 / m2^(3/2)), `Kurtosis` (m4 / m2^2, not excess; both absent when every
value is the same) and `Histogram`. Each state stores its count, minimum, maximum, the sums of
x, x^2, x^3 and x^4 as double-double pairs (about 106 bits; each power exact), and 32 equal bins
over a fixed range: [0, 8) for `LocalDimension`,
[-2, 1) for `OllivierRicciCurvature` and [-24, 8) for `WolframRicciCurvatureScalar`, a value
outside the range counting in the end bin. A value less than 10^-9 bin widths below a bin's
lower edge counts in that bin. Pooling adds these and forms the central moments in
double-double, so the moments are exact to double precision and the
quantiles are histogram quantiles: the bin holding the fraction q of the weight, linear inside
the bin between its edges clipped to [`Min`, `Max`]. `Histogram` maps each non-empty bin's lower
edge to its weight.

**`StepStatistics` volume growth.** Six more `Invariants` entries and six more `VertexInvariants`
distributions fit the growth of balls and spheres about each vertex v of G' (the largest
component above). For r = 0..ecc(v), A(r) = \|S(v, r)\| counts the vertices at distance r,
V(r) = \|B(v, r)\| is the counting measure of the ball, and W(r), the Riemannian measure, counts
the vertices of B(v, r) whose neighbours all lie in B(v, r). Each profile is cut at p, the
largest r at which A(r) is greatest. The quotients of a profile f are q(r) = (log f(r+1) -
log f(r)) / (log(r+1) - log r) for r = 1..p-1, so k = p - 1 of them. A fit regresses q on
x = r(r+1) by least squares, q = c1 + c2 x, over a window of radii. With k < 5 the window is
1..k. Otherwise e(i, j) is the residual standard error of the regression over i..j,
sqrt(max(Σq² - (Σq - b Σx) Σq / m - b Σxq, 0) / (m - 2)) with m = j - i + 1 and b = (m Σxq -
Σx Σq) / (m Σx² - (Σx)²), each sum over i..j. The tolerance is max(2 Q, 10^-10), with Q the
ceil((k-4)/4)-th smallest e over the k - 4 windows of 5 radii. The window is the longest i..j
with e(i, j) <= tolerance, the leftmost of equal length, or 1..k when none is. The ball probe
reads the dimension c1 and the scalar curvature -3(c1 + 2) c2. The sphere probe reads the
dimension c1 + 1 and the scalar curvature -3(c1 + 1) c2.

| Entry | Profile and probe |
|---|---|
| `BallDimension`, `BallScalarCurvature` | V by the ball probe |
| `RiemannianBallDimension`, `RiemannianBallScalarCurvature` | W by the ball probe |
| `SphereDimension`, `SphereScalarCurvature` | A by the sphere probe |

`VertexInvariants` holds the values of those vertices, with 32 bins over [0, 8) for the
dimensions and over [-24, 8) for the scalar curvatures. These are the definitions of the
Infrageometry paclet's `VolumeGrowthObservables` and `DimensionCurvatureFit` with the
`Automatic` window. The breadth-first search from each vertex that the radius takes also gives
A, V and W: the search counts each vertex u at h(u), which is dist(v, u) + 1 when u has a
neighbour farther from v and dist(v, u) otherwise, and W(r) is the number of vertices with
h(u) <= r. Each fit takes O(k²) for its window.

**`StepStatistics` geodesic multiplicity.** For two distinct vertices p, q of one component of
G at distance d, σ(p, q) is the number of shortest paths from p to q. A vertex w lies on one of
them when d(p, w) + d(w, q) = d, and ρ(w) = σ(p, w) σ(w, q) of them pass through it, so the
sum of ρ over those vertices is (d + 1) σ(p, q). The segment entropy of the pair is the entropy
in bits of ρ normalised to sum 1: H(p, q) = -Σ_w (ρ(w) / Σρ) log2(ρ(w) / Σρ). An edge has
H = 1. The pairs below are the ordered pairs (p, q) of distinct vertices joined by a path.

| Entry | Definition | Undefined when |
|---|---|---|
| `GeodeticFraction` | the fraction of the pairs with σ(p, q) = 1 | G has no edge |
| `SegmentEntropy` | the mean of H(p, q) over the pairs | G has no edge |

The per-step key `LogGeodesicCount` maps each distance d to the summary, over the states with a
pair at distance d, of the mean of ln σ(p, q) over the pairs at distance d. σ(p, q) is the
(p, q) entry of A^d, A the adjacency matrix of G (the Infrageometry paclet's
`ShortestPathMultiplicityMatrix`). The breadth-first search from each vertex p that the radius
takes counts the paths: σ(p, p) = 1, and σ(p, w) is the sum of σ(p, u) over the neighbours u of
w with d(p, u) = d(p, w) - 1. The same search sums a(p, w), the sum over the shortest paths from
p to w of the sum of log2 σ(p, x) over their vertices x: a(p, w) is σ(p, w) log2 σ(p, w) plus
the sum of a(p, u) over the same neighbours u. Σ_w ρ(w) log2 ρ(w) = a(p, q) + a(q, p), so the
sum of H over the pairs is the sum over the pairs of log2((d + 1) σ(p, q)) - 2 a(p, q) / ((d +
1) σ(p, q)), and each term comes from p's search. σ is a double, exact below 2^53.

**`StepStatistics` non-lazy Ollivier-Ricci curvature.** `OllivierRicciCurvature` uses the walk of
idleness 1/2: m_x puts 1/2 on x. The non-lazy curvature of an edge x-y uses idleness 0: μ_x puts
1/deg x on each neighbour of x and nothing on x, and κ0(x, y) = 1 - W1(μ_x, μ_y), W1 the
optimal transport cost under the graph distance. W1 is solved as for `OllivierRicciCurvature`,
with the masses scaled to integers by deg x deg y. κ0 lies in [-2, 1].

| Entry | Definition | Undefined when |
|---|---|---|
| `NonLazyOllivierRicciCurvature` | the mean of κ0 over the edges of G | G has no edge |

and the 32 bins over [-2, 1) of the `VertexInvariants` distributions. These are the definitions
of the Infrageometry paclet's `OllivierRicciCurvature`, whose tests give 2/3 on every edge of
K4 and 0 on every edge of P5 and C6.

**`StepStatistics` combinatorial curvature.** The link of a vertex v is the subgraph of G induced
by the neighbours of v. The link is a k-cycle when it has k >= 3 vertices, each joined to exactly
two others in the link, and is connected. A vertex whose link is a k-cycle has the combinatorial
curvature κ_v = 1 - k/6, so 2π κ_v is the angle defect of k equilateral triangles about v. T is
the number of triangles of G.

| Entry | Definition | Undefined when |
|---|---|---|
| `EulerCharacteristic` | V - E + T, with V and E the vertices and edges of G | G is empty |
| `RimFraction` | the fraction of the vertices of G whose link is not a cycle | some vertex lies on no triangle |
| `CombinatorialCurvatureTotal` | the sum of κ_v over the vertices whose link is a cycle | no vertex has a cycle as its link |

For a closed triangulated surface every link is a cycle, `RimFraction` is 0 and
`CombinatorialCurvatureTotal` equals `EulerCharacteristic` (the discrete Gauss-Bonnet theorem):
2 for the icosahedron and the octahedron, 0 for a triangulated torus. `VertexInvariants` gains
`CombinatorialCurvature`, κ_v over the vertices whose link is a cycle, with 32 bins over
[-7, 1). Each vertex's link takes |N(u) ∩ N(v)| for each neighbour u, by merging the two sorted
neighbour lists, and a walk around the link: O(Σ_v Σ_{u ~ v} (deg u + deg v)) per state.

**`StepStatistics` particle measures.** The measures of hypergraph_viz's particle detection

**`StepStatistics` topology.** The family `"Topology"` adds four `Invariants` entries: Betti numbers over GF(2), the field of two elements. The clique complex of G has a k-simplex for each set of k + 1 vertices of G that are joined in pairs. The Vietoris-Rips complex at scale r is Infrageometry's `BallIntersectionComplex[vertices, r, 2, "Metric" -> G]` (Infrageometry@ffa5fe4:Kernel/InfraTopology/BallIntersectionComplex.wl:29-70): a set of vertices is a simplex when every two of them have balls of radius r with a common vertex. Two vertices at distance d have such balls when d <= 2r, so at r = 1 the complex is the clique complex of G², the graph that joins two vertices of G at distance 1 or 2. With V, E, T and Q the vertices, edges, triangles and tetrahedra of a complex and ∂k its boundary maps over GF(2), b0 = V - rank ∂1, b1 = E - rank ∂1 - rank ∂2 and b2 = T - rank ∂2 - rank ∂3.

| Entry | Definition | Undefined when |
|---|---|---|
| `CliqueBetti0` | b0 of the clique complex of G, the number of components of G | G is empty |
| `CliqueBetti1` | b1 of the clique complex of G | G is empty |
| `CliqueBetti2` | b2 of the clique complex of G | G is empty |
| `RipsBetti1` | b1 of the Vietoris-Rips complex at r = 1 | G is empty |

G and G² have the same components, so b0 of the Vietoris-Rips complex is `CliqueBetti0`. The octahedron gives (1, 0, 1), a cycle of 4 or more vertices (1, 1, 0) and a triangulated torus (1, 2, 1). `RipsBetti1` is 0 on the 6-cycle, whose square is the octahedron, and 1 on the 8-cycle.

The computation is Gaussian elimination over GF(2). A breadth-first spanning forest of the complex's graph leaves c = E - V + b0 edges outside it, and a cycle is fixed by its coefficients on those c edges. Each triangle's boundary, as a c-bit row, is reduced against the rows already kept, each kept row pivoting on its highest bit, so rank ∂2 is the number of rows kept and b1 = c - rank ∂2. The tetrahedra's boundaries are reduced the same way as T-bit rows over the triangles. An elimination stops when its rank reaches the dimension of the space (c, or T - rank ∂2), so it keeps at most min(c, T) and min(T - rank ∂2, Q) rows. The cost is at most O(T min(c, T) c / 64 + Q min(T, Q) T / 64) word operations, and the memory min(c, T) c / 8 + min(T, Q) T / 8 bytes. The Vietoris-Rips complex costs the same on G², which has up to V Δ² / 2 edges for the largest degree Δ.

**`StepStatistics` metric tensor.** The family `"MetricTensor"` adds `MetricTensorGap`. Infrageometry's `InfraMetricTensor[G, p, r]` with `"SelectCoordinate" -> Min` (Infrageometry@ffa5fe4:Kernel/RiemannianInfrageometry/InfraMetricTensor.wl:10-27) is a matrix over S_r(p), the vertices at distance r from p. T[v, w] = d(p, u) / r, with u the vertex of the interval I(p, w) = {u : d(p, u) + d(u, w) = r} nearest v, and the least d(p, u) among the nearest. Its entries lie in {0, 1/r, ..., 1}. Infrageometry's tutorial (Infrageometry@ffa5fe4:docs/Tutorials/MetricTensorTutorial.md:211-247) compares the values over all ordered pairs (v, w) with max(cos Θ, 0) for Θ uniform on [0, π], whose distribution function on [0, 1] is F(t) = 1 - arccos(t) / π. The gap of p at r is the integral over [0, 1] of |F_r(t) - F(t)|, with F_r the distribution function of the |S_r(p)|² entries.

| Entry | Definition | Undefined when |
|---|---|---|
| `MetricTensorGap` | the mean of the gap of p at r = ⌊R'/2⌋ over the centre vertices p of G', those of eccentricity R' | R' < 2, R' the radius of G' |

The tutorial reads the first vertex of `GraphCenter`, which depends on the vertex numbering. The mean over every centre vertex is the same for isomorphic states. The tutorial integrates by the midpoint rule on 1000 points. Here F_r is constant on each [k/r, (k+1)/r), and each piece is integrated in closed form with G(t) = t - (t arccos t - sqrt(1 - t²) + 1) / π, the integral of F from 0, split at t* = -cos(π c) where F crosses the constant c. On the 5 x 5 grid the centre is the middle vertex, r = 2, T[v, w] = 1 - d(v, w)/4 on the 8 vertices of S_2, and the gap is 0.0935618363. Each centre takes one breadth-first search from p and one from each vertex of S_r(p), then O(|S|² V): O(C (|S| (V + E) + |S|² V)) for C centre vertices.

**`StepStatistics` holonomy.** The family `"Holonomy"` adds `HolonomyTriangle` and `HolonomySquare`, Infrageometry's holonomy angle at scale r = 1 under `Method -> "Arclength"` (Infrageometry@ffa5fe4:Kernel/InfraFiberBundles/Experimental/InfraLeviCivita.wl:36-93 and 124-133). The directions at a vertex p are its neighbours N(p). The angle between two directions is their distance in G with p deleted, or 2V when deleting p separates them. A transport over an edge p-q maps the smaller of N(p) and N(q) into the larger, one to one, with q in N(p) paired with a continuation. A continuation is a vertex of N(q) farthest from p, and among those farthest in angle from p at q. Among these maps the transports are those with the least sum, over pairs of directions, of the squared difference of their angles. A direction of the larger set outside the image is dropped. The holonomy angle of a closed walk is the least, over the composites of one transport per step, of the mean angle between each direction at the base that the composite moves and its image. Dropped directions are left out, and the angle is 0 when no direction moves.

| Entry | Definition | Undefined when |
|---|---|---|
| `HolonomyTriangle` | the mean over the triangles of G of the mean holonomy angle of its 6 closed walks (3 base vertices, 2 orientations) | G has no triangle, or a vertex of degree above 6 |
| `HolonomySquare` | the same over the chordless 4-cycles of G, with 8 closed walks each | G has no chordless 4-cycle, or a vertex of degree above 6 |

Infrageometry's tests give 1 on the octahedron's triangles, 0 on the triangles of the triangular torus and 0 on the squares of the square torus. The degree bound 6 limits a step to 6 · 5! = 720 transports and a closed walk to 13327 distinct composites, the partial one-to-one maps of 6 directions into 6. The angles take one breadth-first search in G minus v from each neighbour of each vertex v, stopped when the other neighbours are found. Each step scores at most 720 maps in 36 operations each.

**`StepStatistics` equilibrium.** The family `"Equilibrium"` adds the per-step key `Equilibrium`: hypergraph_viz's equilibrium detection (hypergraph_viz@0fb63e5:blackhole/src/equilibrium_analysis.cpp:175-260) over three series of step means. x_s is the `Mean` of `WolframHausdorffDimension`, y_s the `Mean` of `DegreeEntropy` and z_s the `Mean` of `VertexCount` in the step's `Invariants`, each 0 when no state of the step has the entry. The window of step s is the steps s - 19 .. s that have a record, consecutive and back to the first step. The stability of a series over the window is 1 / (1 + σ / |μ|), with μ the mean and σ the sample standard deviation (0 for one step), and 1 when |μ| < 10^-10.

| Key | Definition |
|---|---|
| `DimensionStability`, `DegreeEntropyStability`, `SizeStability` | the stability of x, y and z over the window |
| `OverallStability` | the mean of the three |
| `DimensionTrend`, `SizeTrend` | the least-squares slope of x and of z against the position in the window |
| `Window` | the number of steps in the window, at most 20 |
| `Equilibrated` | `True` when the run has at least 50 steps up to and including s and `OverallStability` >= 0.95 |

hypergraph_viz computes the scores once, for the last step, in single precision, and includes the mean branchial sharpness. Here every step has its scores, in double precision, and the sharpness is left out: it needs `"StepStatisticsBranchial"` `"Overlap"`, and hypergraph_viz gives it stability 1 when it is not computed. hypergraph_viz's degree entropy and vertex count are those of the union of the step's states. Here they are the means over the step's states, weighted as `Invariants` is. A step's scores read only the records of the steps before it, so they are computed as each step's record is made (`StepStatisticsJobs::close_equilibrium`): a step whose predecessor has its scores computes its own, then its successor's when that record is made. The cost is O(20) per step.

**`StepStatistics` branch alignment.** The family `"BranchAlignment"` adds `AlignmentMoment1`, `AlignmentMoment2` and `AlignmentMoment3`: hypergraph_viz's curvature-weighted moment of inertia of a spectral embedding (hypergraph_viz@0fb63e5:blackhole/src/branch_alignment.cpp:29-205 and 410-516), as the paclet's former options `"BranchAlignment"` and `"BranchAlignmentMethod" -> "WolframRicci"` computed it. With L = D - A the Laplacian of G' and 0 = μ1 <= μ2 <= ... its eigenvalues, a vertex v of G' sits at x_v = (u2(v), u3(v), u4(v)), u_k the unit eigenvector of μ_k. Its mass is m_v = \|K_v\| + 1/100, K_v the Ricci scalar of v from `VertexInvariants` `WolframRicciCurvatureScalar`. With c = Σ m_v x_v / Σ m_v, the inertia tensor is I = Σ m_v (\|x_v - c\|² 1 - (x_v - c)(x_v - c)^T), and the entries are its eigenvalues σ1 >= σ2 >= σ3 divided by Σ m_v.

| Entry | Definition | Undefined when |
|---|---|---|
| `AlignmentMoment1`, `AlignmentMoment2`, `AlignmentMoment3` | σ1, σ2, σ3 over Σ m_v | G' has fewer than 4 or more than 256 vertices, or μ5 - μ4 <= 10^-6 μ5 |

The eigenvectors u2, u3, u4 are fixed up to an orthogonal change of basis of their span when μ4 < μ5. Such a change rotates every x_v, and the eigenvalues of I do not change, so the entries are the same for isomorphic states. When μ4 = μ5 the span is not determined by G', and the entries are undefined. With every K_v = 0 the masses are equal, Σ x_v x_v^T is the identity, and each entry is 2/n' for n' vertices of G'.

hypergraph_viz finds the eigenvectors by 100 steps of power iteration from pseudo-random vectors in single precision. Here L is diagonalised in double precision: Householder reduction to a tridiagonal matrix, then the implicit QL iteration with at most 60 iterations per eigenvalue, then Jacobi rotations on the 3 x 3 tensor. The cost is O(n'³) time and n'² doubles for n' vertices of G', on one thread of the state's record. hypergraph_viz's per-vertex output (the projections on the principal axes, oriented by curvature) is not an entry: an axis of a repeated σ has no fixed direction.

**Per-vertex curvature.** With `"IncludeVertexCurvature" -> True` each `"States"` record has
`VertexCurvature`, an association from each vertex of the record's edges that has a neighbour in
G, ascending, to k_v. It is computed from the edges the record lists, so under
`"CanonicalizeStates" -> Full` it belongs to the canonical form. The values are those
`VertexInvariants` pools, from the same function (`hgcommon::sg_geometry_of`). Both engines'
replies compute them while writing the records, which host jobs write in chunks of 256 states.

The radius, the per-radius dimensions and the Ricci scalar take one breadth-first search per
vertex; the per-vertex dimensions used by `FisherInformation` and `LargestComponentDimension`
take a second, and K_v a third, to depth R'; k_v, `OllivierMoranI` and
`OllivierDegreeCorrelation` take O(\|E\|) after the edge curvatures; each edge's
transport problem is solved exactly by successive shortest paths over the (deg x + 1) x
(deg y + 1) supports, with the masses scaled to integers by 2 deg x deg y. Graph construction,
transport and every sum run in caller memory without allocation, so the device can call the
same functions. Geodesic bundle spread and proper time (hypergraph_viz) are not provided: both
are defined from random walks or chosen source vertices, and their shortest-path form is the
eccentricity.

**`StepStatistics` branchial metrics.** With `"StepStatisticsBranchial"`, each step's record
gains per-step keys. Both devices compute them and give the same reply.

`"Graph"`: the branchial graph of step s has the step's states (by the run's state identity) as
vertices, and joins the output states of every branchial pair whose first event's output state
is at step s (the rule of `"BranchialStateEdges"`); a pair of one state with itself adds
nothing. `BranchialDegree` is the summary of the vertex degrees, `BranchialDistance` the
summary of the distances between every two states in one component, `BranchialComponents` the
number of components, and `BranchialDimension` the `WolframHausdorffDimension` of the largest
component (most states, then the greatest dimension, then the least state id), absent when that
component has fewer than 2 states. The same component, as the graph G of "StepStatistics volume
growth", gives `BranchialBallDimension`, `BranchialBallScalarCurvature`,
`BranchialRiemannianBallDimension`, `BranchialRiemannianBallScalarCurvature`,
`BranchialSphereDimension` and `BranchialSphereScalarCurvature` (the means over its vertices
with a fit, absent when none has one), `BranchialOllivierRicciCurvature` (the mean
`OllivierRicciCurvature` of its edges) and `BranchialNonLazyOllivierRicciCurvature` (the mean
non-lazy curvature of its edges).
Under `"ExploreFromCanonicalStatesOnly" -> True` the graph of step s has the classes at step s
as vertices and joins the output classes of every two overlapping matches of each class at step
s - 1 (`hgcommon::qm_expansion_state_pairs`). Every raw state of a class applies every match of
the class, so this is the full-capture graph under `"CanonicalizeStates" -> Full`, and the keys
are equal. *(Gate: `StateStatistics.BranchialGraphUnderQuotientEqualsFullCapture`, every oracle
corpus case, both engines.)*

`"Overlap"`: each state at the step is its set of vertices. The engine gives a new vertex a new
id, so two states share a vertex exactly when both inherited it from a common ancestor, and the
values depend on the history and not on the numbering. A branch is a state at the step, which
is how hypergraph_viz's branchial analysis assigns branch ids (its index within its step).
Over every two states A, B, with U the union of the step's vertex sets and n11 = |A ∩ B|:
`StateOverlap` summarises n11 / |A ∪ B| (0 when both have no vertices), `StateCosineSimilarity`
n11 / sqrt(|A| |B|) (0 when either is empty), and `StateMutualInformation` the mutual
information in bits of membership in A and in B over U: with n10 = |A| - n11,
n01 = |B| - n11, n00 = |U| - |A| - |B| + n11 and p_ab = n_ab / |U|,
max(0, Σ p_ab log2(p_ab / (p_a p_b))), terms with p_ab = 0 left out.
`InitialStateMutualInformation` summarises over the step's states S the same quantity for S and
S0, the union of the vertex sets of the step-0 states (every initial state), over U ∪ S0.
For each vertex held by k of the step's states, `VertexSharpness` summarises 1/k and
`BranchEntropy` log2 k bits; `EdgeSharpness` and `EdgeBranchEntropy` do the same for edges,
where an edge is its ordered list of vertex ids, so two states hold the same edge when both
hold an edge on the same inherited vertices in the same order (this is also the identity under
which `Automatic` merges states). Each id counts once, and each state once under either
`"StepStatisticsWeighting"`. With both `"Graph"` and `"Overlap"`, `OverlapByBranchialDistance`
maps each distance d > 0 between two states of one branchial component to the summary of
n11 / |A ∪ B| over the pairs at distance d; with one of the two it is absent. These need each
state's own vertices, so under `"CanonicalizeStates" -> Full` the run warns and leaves them
out; under `Automatic` a state stands for its identical edge lists.

Cost: the pair pass visits every two states that share a vertex through an inverted index, rows
split over up to one job per worker, and counts pairs per (|A|, |B|, n11, distance), so every
pairwise value is computed once per distinct count tuple; the pairs that share nothing are
counted per (|A|, |B|) from the size histogram. With `"Graph"`, each row adds one breadth-first
search of its branchial component, the cost of `BranchialDistance`. Both engines' replies run
this pass on host job-system workers from the states and branchial pairs, through
`hgcommon/branchial_rows_core.hpp` and `hgcommon/branchial_overlap_core.hpp` (ARCHITECTURE.md,
"StepStatistics in the job system"); the GPU engine's reply counts the rows of a step of 2048
states or more on the device.

**`StepStatistics` state matrices.** `"StepStatisticsMatrices"` names any of six state x state
matrices, which each step's record gives under `StateMatrices`: an association whose `States`
lists the step's state ids ascending (the ids of `"States"`, under the run's state identity) and
which holds each matrix asked for as a k x k array of reals, row and column i for the i-th
state. The overlap and the cosine of a level (vertex or edge) are a `SparseArray` with implicit
value `0.` when fewer than half of the step's k (k - 1) / 2 pairs share an element, and a packed
array otherwise; the mutual information, nonzero for two disjoint states, is always a packed
array. Below half, the `SparseArray` is under 6 k² + O(k) bytes in WXF against 8 k² (a real and a
column index of at most 4 bytes per nonzero), and its kernel `ByteCount` is about the packed
array's or less (16 bytes per nonzero against 8 per cell). `StateOverlap`, `StateCosineSimilarity` and `StateMutualInformation` hold, for every
two states, the value the summary of the same name summarises; `StateEdgeOverlap`,
`StateEdgeCosineSimilarity` and `StateEdgeMutualInformation` are the same three with each state
as its set of edges (an edge is its ordered list of vertex ids, as for `EdgeSharpness`) and U the
union of the step's edge sets. A pair's value is computed once from (n11, the smaller size, the
larger size) and written to both cells, so the matrix is symmetric bit for bit and its cells above
the diagonal are the values the summaries read. The diagonal is each state against itself: 1 for
the overlap and the cosine (0 for an empty state), and for the mutual information the entropy in
bits of membership in the state over U. `"StepStatisticsMatrixLimit"` bounds the bytes a step's
matrices take while they are built: 16 k² per matrix (its reals and their reply) and 2 k (k - 1)
per level (vertex, edge) for the shared counts. `Automatic`, the default, is a quarter of the
host's available memory as the process reads it at its first run. A step that needs more has no
`StateMatrices`, and the run warns with the step, its state count and the bytes. State ids are numbered by the run (§5.1), so two runs give the same
matrices up to a renumbering of the states. The admission is `"Overlap"`'s.

Cost: n11 for every two states that share an element comes from the overlap pass's rows (one
pass over the vertex sets, one over the edge sets), each pair writing its own cell of a
k (k - 1) / 2 triangle. After its count the same row job, or on the device the same warp,
computes its row's values (`hgcommon::bo_matrix_row`): O(k) per row and matrix, O(k²) per matrix
over the step's rows. The device runs the rows of a step of 2048 states or more. The reply writes
each matrix from the filled k x k array (`Writer::write_packed_reals` or
`Writer::write_sparse_reals`), the same bytes for either device.
*(Gate: `reference/verify_state_statistics.wls`: the engine against
`reference/StateGeometryReference.wl`, an independent Wolfram Language implementation, on the
corpus and on random rules; the two Function Repository metrics against ResourceFunction itself.
Hand-checked values: `StateGeometryCore.*`.)*

### 5.5 Proof obligations, and the gates that discharge them

1. **quotient ≡ full capture** on every observable, incl. cyclic rules — `cost_matrix` (oracle
   EXACT), `RelationCoherence`, the golden corpus (12/12, CPU == GPU).
2. **TR = the transitive reduction** of the causal DAG, order-independent —
   `causal_tr_exactness_probe`, `CausalTrExactnessTest.*` (the replay's kept set equals the
   reduction of its own stored relation at 1-64 workers), the search shared as
   `hgcommon/reach_core.hpp`.
3. **Schedule-independence** of the whole observable output — `CausalDeterminism.*` (fingerprints
   at 1–32 threads, per-run claim/enumeration invariants), `SamplingReproducibility.*`.
4. **The concurrent structures enumerate what they claim** — the GenMC suite (19 harnesses; the
   containers' exactly-once and completeness properties, each calibrated), TLA+ for
   `SegmentedArray`'s segment invariant.

### 5.6 Relationship to the reference (oracle, not spec)

`MultiwaySystem` / `MultiwayReference.wl` is an **oracle for validation, not a specification to
conform to.** The engine matches it exactly where the target is a genuine invariant — states, raw
events, causal, branchial — and that is a hard gate. `Positional` event identity is a parity
mode: `Sort[]`-tie-break-defined (§4.2), amber, opt-in, never a hard gate — freezing its numbers
would freeze one build's tie-break. `Automatic` is allowed to differ from upstream's `Automatic`
exactly where upstream's depends on the tie-break; where an invariant target exists, it is
adjudicated step-exact (§4.2).
